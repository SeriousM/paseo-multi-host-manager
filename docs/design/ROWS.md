# Settings rows -> real keys (Paseo 0.13.2)

Source of rows: `mockup/host-matrix-v2.html` (`settingRows`). Verified 2026-10-29 on two throwaway daemons (Windows, Debian 12 under WSL2) with
actual calls: `getDaemonConfig`, `patchDaemonConfig`, `reloadDaemonConfig`, `getDaemonStatus` (direct and routed through a hub), plus `config.json`
read/write by a probe plugin's own RPC. Results were identical on both OS.

Terms:
- **config.json path** = key in `$PASEO_HOME/config.json` (the mockup keys are these). **config.get/patch path** = key in the "mutable" shape returned by
  `getDaemonConfig` and accepted by `patchDaemonConfig`. The two differ (`daemon.mcp.injectIntoAgents` on disk is `mcp.injectIntoAgents` over RPC).
- **live** = `patchDaemonConfig` applies immediately, persists to `config.json`, no further step.
- **reload** = write `config.json`, then `reloadDaemonConfig`. The daemon answers `{appliedPaths, restartRequiredPaths, overrideControlledPaths}`, which is the authoritative classification.
- **restart** = `reloadDaemonConfig` lists the path in `restartRequiredPaths` (running daemon unchanged). The restart itself was not exercised.

## Rules that follow from the tests

1. **`config.patch` silently ignores unknown keys** (it returns success and changes nothing). Compare the returned config, or re-read, before reporting success.
2. **Only these keys are patchable:** `relay.{enabled,requireProtectedSecurity}`, `mcp.injectIntoAgents`, `browserTools.enabled`, `providers` (+`removeProviders`), `metadataGeneration.providers`, `autoArchiveAfterMerge`, `enableTerminalAgentHooks`, `appendSystemPrompt`, `terminalProfiles`, `agentProfiles`, `pluginsEnabled`, `plugins`. Everything else is file + reload or restart.
3. **Reload-applied set** (from the daemon's own `RELOADABLE_PATHS`; exercised above for the rows in the table, the remainder read from the 0.13.2 server source only): `daemon.relay.*`, `daemon.mcp.*`, `daemon.browserTools.enabled`, `daemon.hostnames`, `daemon.cors.allowedOrigins`, `daemon.trustedProxies`, `daemon.git.*`, `daemon.autoArchiveAfterMerge`, `daemon.enableTerminalAgentHooks`, `daemon.appendSystemPrompt`, `daemon.terminalProfiles`, `daemon.agentProfiles`, `app.baseUrl`, `agents.providers`, `agents.catalogRefreshTimeoutMs`, `agents.metadataGeneration`, `agents.skills.selection`, `pluginsEnabled`. Any other changed path ends up in `restartRequiredPaths`.
4. **`restartRequiredPaths` always contains `plugins.<id>.*` entries** for plugins installed after the daemon started; filter them out before judging a reload.
5. **`config.json` strictness:** the file is parsed with a strict schema; an unknown key makes `reloadDaemonConfig` fail (the running daemon keeps its state, restoring the file and reloading again worked). `config.json` holds the bcrypt password hash and is mode 0600; a plain `writeFile`+rename by a plugin produced mode 0644 on Linux until the next reload re-tightened it. Companion writes must set 0600 and write atomically.
6. **Routed access works the same:** `patch`, `reload`, `getDaemonStatus` and the companion RPC were also called through a routed client (hub-style) on both hosts.
7. **Readable but not patchable in `config.get`:** `hostnames`, `cors.allowedOrigins`, `trustedProxies`, `git.*`, `app.baseUrl`, `catalogRefreshTimeoutMs`, `mcp.enabled`, `skills.selection`. Candidate extra rows (copy = file write + reload via companion).
